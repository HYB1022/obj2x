> [!NOTE]
> **v2.7.3부터 이름이 obj2x에서 Bus Depot으로 바뀌었습니다.** 실행 파일은 `BusDepot.exe`, 설정은 `BusDepot.ini`입니다. 예전 설정(`obj2x.ini`)은 처음 실행할 때 그대로 옮겨 오고, 예전 버전의 자동 업데이트와 바로 가기(`obj2x.exe`)도 계속 동작합니다.

파일을 하나씩 열고 옵션을 맞추고 Convert를 누르던 작업을, **폴더만 지정하면** 자동으로 해 줍니다.

- **일괄 변환**: 폴더 안의 `.obj`를 Blender 2.79b로 `.x`로, 이어서 OmsiXConv로 `.o3d`까지 변환합니다. OmsiXConv의 체크박스(`X-File: z up` 등)는 정해 둔 상태로 알아서 맞춥니다.
- **병렬 처리**: OmsiXConv를 여러 개 동시에 띄우고, 그 창들은 화면 밖으로 치워 이 도구의 창만 보이게 합니다.
- **빠른 변환 (실험적)**: Blender와 OmsiXConv 없이 obj에서 바로 `.o3d`를 만듭니다. 파일당 0.1초 안팎입니다.
- **결과 표**: 파일별 정점·삼각형·재질 수, 걸린 시간, 상태(OK / 주의 / 실패)를 한눈에 보여 줍니다.
- **OMSI 제작**: o3d 모델로 오브젝트(`.sco`)를, 차선·인도 값으로 도로 스플라인(`.sli`)을 만들어 OMSI 폴더에 바로 넣습니다.
- **모델 보기**: 버스 `model.cfg`나 오브젝트 `.sco`를 텍스처까지 3D로 보고, Blender 파일(`.blend`)이나 OBJ로 저장합니다.

`.o3d`는 `.x`와 같은 폴더에 생기고, 파일 이름은 obj 이름과 같습니다 (`face.obj` → `face.x` → `face.o3d`).

## 필요한 것

| 필요한 것 | 설명 |
| --- | --- |
| Windows 10 / 11 | 실행에 필요한 .NET Framework 4.x는 Windows에 기본 포함되어 있습니다 |
| [Blender 2.79b](https://download.blender.org/release/Blender2.79/) | 2.79 기본 포함 `Import-Export: DirectX X Format` 애드온이 켜져 있어야 합니다. 다른 버전(2.8 이상)은 지원하지 않습니다 |
| OmsiXConv (Omsi X to O3D Converter 1.0) | **이 저장소에 포함되어 있지 않습니다.** 별도로 구해서 `OmsiXConv.exe` 위치를 지정하세요 |

obj를 만드는 Blender는 버전이 상관없습니다. 변환에만 2.79b가 필요합니다. 빠른 변환만 쓴다면 Blender와 OmsiXConv 모두 없어도 됩니다.

## 사용법

1. [Releases](https://github.com/HYB1022/obj2x/releases/latest)에서 최신 `BusDepot.zip`을 받아 **쓰기 가능한 폴더**에 풉니다. 설정은 같은 폴더의 `BusDepot.ini`에 저장됩니다.
2. `BusDepot.exe`(또는 `BusDepot.bat`)를 실행합니다. 처음 실행하면 면책 조항에 동의해야 합니다.
3. `고급` 탭에서 Blender 2.79의 `blender.exe`와 `OmsiXConv.exe` 위치를 지정합니다. 한 번 지정하면 저장됩니다.
4. `변환 마법사`에서 변환 방식을 고르고, OBJ 폴더(입력)와 출력 폴더를 지정한 뒤 변환을 시작합니다. obj 폴더(또는 obj 파일)를 창이나 `BusDepot.exe` 아이콘 위에 끌어다 놓으면 마법사가 그 폴더로 바로 열리고, 최근에 쓴 폴더를 눌러 고를 수도 있습니다.
5. 진행 상황은 `대시보드`의 진행 막대와 `로그` / `결과 표` 탭, 작업 표시줄의 Bus Depot 단추에 표시됩니다. 다른 창을 보고 있는 동안 변환이 끝나면 작업 표시줄 단추가 깜빡입니다.

| 변환 방식 | 하는 일 |
| --- | --- |
| **DirectX → O3D** (권장) | Blender 2.79b로 `.x`를 만든 뒤 OmsiXConv로 `.o3d`까지 변환하는 표준 방식 |
| **Blender .x 단독** | OmsiXConv 없이 `.x` 파일만 만듭니다 |
| **FastO3D** (실험적) | 내장 변환기로 obj에서 바로 `.o3d`를 만듭니다. 아래 [빠른 변환](#빠른-변환-실험적-기능)을 먼저 읽어 보세요 |

> [!NOTE]
> OmsiXConv로 변환하는 동안에는 보이지 않는 OmsiXConv 창이 입력을 받고 있으니 마우스와 키보드를 가급적 건드리지 마세요.

## 기능

| 기능 | 설명 |
| --- | --- |
| 하위 폴더 포함 | 입력 폴더 안의 하위 폴더까지 obj를 찾아 변환합니다. 출력 폴더에도 같은 하위 폴더 구조로 `.x`/`.o3d`가 생깁니다 |
| 변경된 obj만 변환 | `.o3d`보다 새로 수정된 obj만 변환합니다 (`.x`만 만들 때는 `.x`와 비교). 모델링하며 반복해서 내보낼 때 유용합니다 |
| 중지 | Blender와 OmsiXConv를 모두 종료하고 대기열을 비웁니다 |
| 실패한 것만 다시 | 실패한 파일이 있으면 끝난 뒤 `결과 표`에 표시되고, `실패한 것만 다시`로 그 파일만 다시 돌립니다. `.x`까지 만든 파일은 O3D 단계부터, Blender나 빠른 변환에서 실패한 파일은 처음부터 다시 합니다 |
| 텍스처 누락 경고 | 변환하기 전에 `.mtl`에 적힌 텍스처가 폴더에 있는지 확인하고, 없으면 목록을 보여 주며 계속할지 묻습니다 |
| 동시 실행 개수 | OmsiXConv를 몇 개까지 동시에 띄울지 정합니다. 기본값은 PC 논리 코어 수 − 1입니다. OmsiXConv는 코어 하나만 쓰므로 코어 수보다 많이 띄우면 오히려 느려집니다 |
| 업데이트 확인 | 시작할 때 GitHub에서 최신 릴리스를 확인하고, 새 버전이 있으면 `정보` 메뉴의 `업데이트` 표시로 알려 줍니다 |

### 고급 / 설정 탭

- **OmsiXConv 세부 옵션** (`고급`): `z up`, `Separate Files`, `Show Details of X`, `Remove Specular`, `Opt. Materials`, `Opt. Vertices`, `All Normals Up`, `Use Submesh Local Pos. as Global Pos.` 변환할 때마다 여기서 정한 상태로 자동 설정됩니다. 기본값은 `z up` 해제, `Remove Specular` / `Opt. Materials` / `Opt. Vertices` 체크입니다.
- **Blender .x 내보내기 추가 옵션** (`고급`): 내보내기 애드온의 옵션을 `이름=값` 한 줄씩 적습니다 (예: `ApplyModifiers=True`). 실행 로그의 `x exporter options:` 목록에 있는 이름만 적용되고, 없는 이름은 `ignored options`로 표시됩니다.
- **성공 시 .x 파일 삭제** (`설정`): O3D 변환에 성공하면 중간 파일인 `.x`를 지웁니다.
- **글꼴** (`설정`): 나눔스퀘어 네오(기본), Noto Sans KR, MiSans, Windows 시스템 글꼴 중에서 고릅니다. 나눔스퀘어 네오와 Noto Sans KR은 `fonts` 폴더에 들어 있습니다. MiSans는 라이선스상 함께 배포할 수 없으니 [샤오미 HyperOS 글꼴 페이지](https://hyperos.mi.com/font)에서 받아 Windows에 설치하거나 `fonts` 폴더에 넣으세요. 없으면 나눔스퀘어 네오로 표시됩니다.
- **언어 파일** (`설정`): 한국어, English, Deutsch, 日本語, 中文을 지원합니다. `언어 파일` 버튼을 누르면 exe 옆에 `lang` 폴더와 번역 틀(`_template.json`)이 생깁니다. 틀을 복사해 `<언어 코드>.json`(예: `fr.json`)으로 저장하고 번역하면 언어 목록에 나타납니다. 기본 언어와 같은 이름으로 저장하면 그 언어의 일부 문구만 바꿀 수도 있습니다.

## OMSI 오브젝트 / 스플라인 만들기 / 모델 보기

OMSI 2 폴더는 Steam 설치 정보에서 자동으로 찾습니다. 못 찾으면 각 화면의 `OMSI 2 폴더` 줄을 눌러 `Omsi.exe`가 있는 폴더를 지정하세요.

- **오브젝트 만들기**: o3d 모델이 있는 폴더를 고르면(창 위에 끌어다 놓아도 됨) 모델 목록이 나옵니다. 만들기를 누르면 `Sceneryobjects\<폴더 이름>`에 `model\`, `texture\`, `.sco`가 생기고 맵 에디터의 오브젝트 목록에 나타납니다.
  - 모델마다 오브젝트를 하나씩 만들거나, 모두 합쳐 오브젝트 하나로 만들 수 있습니다.
  - 충돌, 위를 다닐 수 있음(다리·승강장), 그림자, 고정을 켜고 끌 수 있습니다.
  - 알파 채널이 있는 텍스처(tga/dds/png)는 투명 재질(`[matl_alpha]`)로 자동 설정합니다. 잘라내기(나뭇잎·철망) 또는 반투명(유리) 중에서 고릅니다.
  - 텍스처는 모델 폴더, 그 옆, `texture` 폴더에서 찾아 복사합니다. 못 찾은 텍스처는 끝난 뒤 목록으로 알려 줍니다.
- **스플라인 만들기**: 차선 수, 차선 폭, 양방향/일방통행, 인도 폭, 연석 높이를 정하면 미리보기가 바로 바뀌고, 만들기를 누르면 `Splines\<폴더 이름>`에 `.sli`와 `texture\`가 생깁니다.
  - 차가 다니는 길(차선마다, 오른쪽 통행)과 사람이 다니는 길(인도마다)이 함께 들어갑니다. 양방향인데 차선 수가 홀수면 남는 한 차선을 왼쪽(역방향)과 오른쪽(정방향) 중 어디에 둘지 고릅니다.
  - 노면·인도 텍스처를 고르지 않으면 기본 아스팔트와 보도블록 텍스처를 만들어 넣습니다. 노면 텍스처는 도로 전체에 한 번 또는 차선마다 한 번 펼칠 수 있습니다.

- **모델 보기**: 버스의 `model.cfg`나 오브젝트의 `.sco`를 고르거나 창에 끌어다 놓으면 텍스처까지 입혀 3D로 보여 줍니다. 끌어서 돌리고, 오른쪽 버튼으로 옮기고, 휠로 확대합니다.
  - 처음에는 밖에서 보이는 가장 자세한 LOD의 부품만 켜집니다. 조건부 부품(`[visible]`)은 변수마다 첫 번째 값만 켜지고, 부품 목록에서 하나씩 켜고 끌 수 있습니다. `밖` / `안` / `전체`로 한 번에 바꿀 수도 있습니다.
  - **도색**: `[CTC]` 도색 폴더의 `.cti`를 골라 그 도색의 텍스처를 입히고, `.cti`의 `[setvar]` 옵션대로 조건부 부품을 켜고 끕니다. 한 `.cti`에 도색이 여러 개 있으면 따로따로 고를 수 있습니다. 차량 스크립트(`.osc`)가 도색 값을 보고 정하는 옵션(연식에 따른 문 모양 등)도 스크립트를 간단히 돌려서 맞춥니다. 정하지 않은 변수는 OMSI처럼 0으로 봅니다. 처음에는 첫 번째 도색이 골라집니다. 투명은 `[matl_alpha]`가 있는 재질에만 적용합니다(OMSI와 같게).
  - OMSI처럼 앞면만 그립니다. 노멀이 뒤집힌 면은 게임에서처럼 보이지 않고, `뒷면도 보기`를 켜면 양면으로 그립니다.
  - 게임에서 애니메이션으로 제자리에 옮겨지는 부품(꽂는 표지판 등)은 파일 속 위치가 차체 밖이라 처음에는 꺼 둡니다. 바퀴 회전, 문 열림 같은 애니메이션은 보여 주지 않습니다.
  - **Blender 파일로 저장**: 켜 둔 부품을 설치된 Blender 중 가장 새 버전(Program Files, Steam에서 자동으로 찾음. 직접 고를 수도 있음)으로 불러와 텍스처까지 파일 안에 넣은 `.blend`로 저장합니다. 부품마다 오브젝트가 하나씩 생기고, 방향은 OMSI와 같습니다(z 위, 차 길이는 y). Blender 없이 `.obj` + `.mtl`로만 저장할 수도 있습니다.
  - 암호화된 o3d(OMSI 기본 차량 등)는 열지 않습니다.

> [!NOTE]
> 만든 파일은 OMSI의 기본 형식만 씁니다(밤 텍스처, LOD, 신호등, 교차로 등은 넣지 않음). 더 손볼 것은 만들어진 `.sco` / `.sli`를 메모장으로 열어 고치세요.

### 빠른 변환 (실험적 기능)

> [!WARNING]
> **실험적 기능입니다.** OmsiXConv의 동작을 파일 형식에서 역으로 분석해 만든 것이라 모든 모델에서 같은 결과가 나온다고 보장할 수 없습니다. 중요한 모델은 처음에는 기존 방식과 결과를 비교해 보고, 문제가 있으면 기존 방식으로 변환하세요.

OmsiXConv의 `.o3d`와 대조해 검증한 범위에서는 삼각형·재질·UV가 같습니다(노멀은 0.001 이내 차이, 정점 수는 몇 개 달라질 수 있음). 다음은 아직 지원하지 않거나 검증하지 못했습니다.

- 오브젝트가 여러 개로 나뉜 obj: 하나의 메시로 합쳐지며 오브젝트별 기준점은 유지되지 않습니다. OmsiXConv와 결과가 같은지는 확인하지 못했습니다
- 정점 또는 삼각형이 65,535개를 넘는 모델 (실패로 표시됨)
- OmsiXConv 세부 옵션(`z up` 등)과 Blender 추가 옵션은 적용되지 않음

## 업데이트

시작할 때 새 버전이 있으면 사이드바의 `정보` 메뉴 오른쪽에 `업데이트` 표시가 생기고, `정보` 탭의 `업데이트` 줄에도 `업데이트` 표시가 올라옵니다. `업데이트`를 누르면 릴리스의 zip을 내려받아 같은 폴더에 덮어쓰고 다시 시작합니다.

- 설정(`BusDepot.ini`)은 그대로 유지됩니다.
- 기존 `BusDepot.exe`, `BusDepot.bat`, `BusDepot.py`(v2.7.2 이하는 `obj2x.*`), `obj2x_gui.ps1`은 `BusDepot_backup` 폴더에 보관됩니다.
- v2.0(PowerShell 버전)에서도 그대로 최신 버전으로 업데이트됩니다. `obj2x_gui.ps1`은 이제 `BusDepot.exe`를 실행하는 런처입니다.
- 시작할 때 GitHub에 접속하는 게 싫으면 `설정`에서 `시작 시 업데이트 확인`을 끄세요.
- 내려받은 파일의 무결성은 따로 검증하지 않습니다. 이 저장소의 릴리스를 신뢰하는 경우에만 사용하세요.

## 문제 해결

| 증상 | 확인할 것 |
| --- | --- |
| Windows가 실행을 막거나 경고함 | `BusDepot.exe`는 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다. `추가 정보` → `실행`을 누르거나, 소스(`src/`)를 확인하고 `build.bat`으로 직접 빌드하세요 |
| `blender.exe` 관련 오류 | 2.79b의 `blender.exe`를 지정했는지 확인하세요 (자동 감지는 하지 않습니다) |
| `E/A-Fehler 103`이 간혹 뜸 | OmsiXConv 쪽 오류입니다. 자동으로 최대 3번 재시도하고, 계속 나면 동시 실행 개수를 줄여 보세요 |
| 로그에 `OmsiXConv 창을 못 찾음` | OmsiXConv 경로가 맞는지, 다른 프로그램이 그 창을 가로막지 않는지 확인하세요 |
| 로그에 `파일 선택창을 못 찾음` | 괄호 안에 나온 창 목록을 이슈로 알려주세요 |
| 방향이 틀어진 모델 | `고급` 탭에서 OmsiXConv의 `z up` 상태를 확인하세요 (기본은 해제) |

문제가 있으면 로그 내용과 함께 [이슈](https://github.com/HYB1022/obj2x/issues)로 알려주세요. 제 환경에서 만든 도구라 다른 환경에서는 동작이 다를 수 있습니다. 파일이 큰 `.x`(수 MB 이상)는 변환이 오래 걸릴 수 있습니다.

## 직접 빌드하기

`build.bat`을 실행하면 Windows에 기본 포함된 C# 컴파일러(.NET Framework 4)로 `src\Core`(변환 로직)와 `src\App`(WPF 화면)을 `BusDepot.exe`로 빌드합니다. 따로 설치할 것은 없습니다.

```bat
build.bat
BusDepot.exe --selftest
```

`--selftest`는 설정·문구·변환기·화면 구성을 자동으로 점검하고, 결과를 같은 폴더의 `BusDepot_selftest.txt`에 `PASS` / `FAIL` 줄로 남깁니다.

## 면책 조항

처음 실행하면 면책 조항이 표시되고, 내용에 동의해야 사용할 수 있습니다. 동의 여부는 `BusDepot.ini`에 저장되며, `정보` 탭의 `면책 조항`을 누르면 다시 볼 수 있습니다. 이 도구는 개인이 만든 비공식 도구이며 Blender, OmsiXConv, OMSI와 관련이 없고, 변환 결과나 파일 손상 등에 대해 보증하거나 책임지지 않습니다. 중요한 파일은 백업하고 결과를 직접 확인하세요.

이 저장소에는 Blender와 OmsiXConv가 포함되어 있지 않습니다. 각 프로그램의 라이선스는 각자 따릅니다.
